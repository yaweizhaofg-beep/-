# 后端交付说明

交付日期：2026-10-15。产品：星核耀火数据管理台。本目录可独立运行，不依赖仓库其他项目。

## 接手顺序

```sh
cd studio-prototype
npm test
npm run build
npm run verify
npm run fixtures
npm run dev
```

前端页面、交互、假设案例、业务计算、HTTP适配器和测试已实现；真实后端和制作软件对接待实现。`artifacts/studio-response.json` 从当前虚构工厂导出，可作为 `/api/v1/studio` 首次联调完整响应；不是生产数据库，不能导入生产环境。先体验演示，再按接口契约实现服务，修改 `public/config.js` 切换HTTP模式。

## 数据职责

| 数据或动作 | 权威录入端 | 网页行为 |
|---|---|---|
| IP立项、预计起止时间、初始参与名单 | 网页 | 提交并关联软件项目 |
| 原始员工及在职状态 | 后端/制作软件 | 同步员工池，网页配置小组归属和角色 |
| 员工指派、首次推理、分镜生成、个人网盘上传 | 制作软件 | 同步并只读展示 |
| 组长点完成、个人最终有效时长、统一网盘链接 | 制作软件 | 只读；确认时间作为制作结束时间 |
| 接收交付、记录投放事实和累计发布数据 | 网页运营 | 接收、编辑和查询，不实际执行平台发布 |
| 模型扣费、退款、成功视频输出数 | 后端/制作软件 | 日期和模型筛选展示 |
| 单页大屏、位置锁定和布局 | 网页 | 保存配置和展示 |

软件写入路由、消息队列和鉴权由后端设计。适配器中保留的旧任务/审核/台账写方法不是当前网页开放入口，不应据此重新开放网页修改制作节点。

## 不可混淆的业务口径

1. 员工节点：立项拆分 → 指派待开始 → 首次推理制作中 → 上传个人百度网盘后制作完成、待组长确认 → 组长最终完成并回填有效时长及统一网盘后项目完成、进入运营。旧任务状态不能代替这些事件。
2. 推进详情、项目“任务”和小组轮播共用 `employeeWorkRows/employeeProjectStage`；员工按当前小组展示，同一人参与多剧分别保留状态。转组不改写历史积分、时长或原项目剧组。
3. 真实接入应提供 `productionAssignments` 和 `inferenceStartedAt`。不要等生成成功才同步正在制作；成员名单/旧任务/generatedAt仅为兼容依据。
4. `productionUploads` 应表达员工在该剧本轮交付完成。原型中的分集上传是节点示例，后端不能把某一集上传误认整部剧的个人交付。
5. 未完成剧的百分比使用 `productionProgress` 完整分镜汇总；完成剧显示确认有效分钟。不能用分页明细数冒充整剧分母。
6. 有效时长源字段为秒、展示为分钟。人效=净积分/有效分钟，越低越省；金额/有效分钟是另一指标，单位分开。
7. 模型环图按扣费积分占比，退款单列；净消耗=扣费-退款。成功视频数为成功输出数，不是请求数或分镜数。
8. 发布累计值按项目+平台+作品ID取最新快照，历史累计值不相加。正式每日更新由后端任务完成；人工回填与自动采集的覆盖策略要统一。
9. 大屏一页，24×12网格。局部换位只改选中和目标两个模块；`adaptive`允许内容拟合新区域，`locked`固定位置尺寸。锁定保存/恢复后仍有效。
10. 日期按北京时间解释。预计完成缺失显示待设置；制作完成时间取组长最终有效交付确认时间，不能由员工上传或运营发布替代。

## 首轮服务实现

1. 登录/会话/退出，账号管理员开通，无注册；Cookie会话、资源权限、CSRF校验由服务端完成。
2. GET studio完整当前对象，所有员工、项目、生产事件、交付和运营记录有稳定ID。
3. 网页写入：IP立项/关联、小组与成员、大屏保存/软删除/恢复、运营接收与投放回填。
4. 软件联动：首次完整同名唯一匹配，绑定后保存两端ID，重名不可任意选择第一条。
5. 最终交付事务同时确认员工有效时长、制作结束和运营待办；事件幂等，旧交付版本不接受新运营回填。
6. version乐观锁、409冲突、审计、退款归属、同步事件ID去重、撤回与更正。

## 已知边界与需对齐事项

- studio目前为完整快照，前端做筛选。生成明细的40行分页是客户端分页；海量数据需新增服务端分页端点并修改 `src/ui/production.js`，不能把局部明细当全量计算。
- 个人交付范围、返工状态回退及最终有效时长必须覆盖的员工集合，需与制作软件确认；前端基础校验不等于完整源系统流程校验。
- 当前为管理员原型视角，无网页角色管理。管理员/组长/运营的数据范围和操作权限需服务端落实。
- 当前通知是网页待办和周期刷新，无短信、站外通知、WebSocket、后台预警推送服务。
- 网盘只保存链接/提取码，不上传文件，也不确认文件能否下载；访问控制与脱敏由业务确定。
- 默认月份2026-10、600万累计积分、人员和平台数据全为假设案例；上线需明确真实期初与默认月份。
- 实际价格换算、平台授权、真实员工照片和剧集封面尚未接入。

## 验收走查

错误密码 → 登录 → 总览 → IP立项及同名关联 → 员工池分组/转组 → 软件同步指派/首次推理/上传/组长完成并核对节点一致 → 运营接收最新版本后回填 → 模型日期/输出/净消耗核对 → 大屏多项目范围、局部移动、缩放、锁定、保存、删除恢复、全屏退出。

正式后端还需测试401/403、资源越权、409、重复事件、交付撤回、缺失个人时长、净退款为负、离职历史、多平台同剧和跨组历史。前端测试不替代服务联调与权限测试。
