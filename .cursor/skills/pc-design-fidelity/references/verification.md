# 视觉与桌面交互验收

在代表性页面初步实现后开始验证；共享组件改动后检查受影响页面。规模与本轮修改匹配，不要求所有微调都新增自动化测试。

## 对照条件

记录设计和实现双方的页面/状态、视口 CSS 像素尺寸、缩放、滚动位置和数据。等字体与图片加载完成；固定随机数据和非必要动画。浏览器外框不要计入网页尺寸，物理截图像素不要误当 CSS 像素。

拿到同条件的原型截图和本地实现截图后实际打开比较。用当前环境可用的浏览器/截图工具；能做叠加或图像差异就用于定位，但抗锯齿、字体与动效差异会影响指标，不能把单个差异百分比当质量结论。

若没有运行/截图工具，记录“未视觉验证”，仍完成能做的代码和构建检查；不能声称像素级还原。只有缺失证据真正阻塞下一步时才让用户补充材料。

## 修正优先级

1. 页面缺失、路由错误、主流程断开、布局结构/滚动区域错误。
2. 应用壳比例、字体、主内容宽度、背景层次、控件与信息密度。
3. 间距、对齐、圆角、描边、阴影、图标尺寸与素材裁切。
4. hover/focus/选中/禁用、弹层与提示、动效节奏。

发现误差应记录具体位置与表现（例如“侧栏偏宽导致标题提前换行”），定位 token/共享组件原因后修正，避免逐页添加抵消误差的临时样式。

## 完成条件

| 维度 | 要看的证据 |
| --- | --- |
| 页面覆盖 | 需求清单中的页面与状态逐项有入口和结果，未知项明示 |
| 视觉 | 同视口、同状态的实际截图；无未解释的显著布局/字体/素材差异 |
| 交互 | 亲自跑通代表性操作、返回/取消/重试；表单及状态反馈可观察 |
| 桌面适配 | 基准视口、较窄和较宽窗口；控件不被遮挡，滚动与键盘焦点可用 |
| 工程 | 项目实际 build/typecheck 和适用检查通过；检查控制台错误与资源加载 |
| 桌面原生 | 范围包含原生能力时，在真实桌面壳验证；否则明确未验证 |

只为易回归且重要的行为添加测试，例如路由切换后编辑状态保留、表单校验、关键弹窗焦点或主流程。检查共享组件的代表性消费者；不为样式常量、内部实现镜像编写无价值测试。

## 轻量记录格式

将下面表格用于 `docs/ui-implementation.md`；按需扩充，不建立多个重复台账。

| 页面/状态 | 来源节点或入口 | 代码位置 | 状态 | 证据/差异 |
| --- | --- | --- | --- | --- |

状态可用：未读取、已读取、实现中、已实现待验证、已验证、阻塞。推断补齐的状态标明“推断”，不要写成原型已有。

每轮交付可用四句话：本轮完成范围；实际验证结果与截图路径；本地预览入口；明确的缺口/取舍。无需长篇重述所有过程。
